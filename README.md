# POV Overlay

本地 GPX 视频叠加层编辑器。前端采用 **Vue 3 + TypeScript + Hikari**，桌面端采用 **Tauri 2 + Rust**。

支持画布排布、实时预览和独立透明或绿幕叠加层视频导出。视频与图片素材用于预览。

## 启动

要求 Node.js 22.13+、pnpm 11.24.0（版本见 `package.json` 的 `packageManager`）、Rust stable，以及 [Tauri 系统开发依赖](https://v2.tauri.app/start/prerequisites/)。

```sh
pnpm install --frozen-lockfile
pnpm tauri dev
```

只启动浏览器开发预览：

```sh
pnpm dev
```

访问 `http://127.0.0.1:1420`，导入自己的 GPX。视频和图片均为可选背景；只有 GPX 也能播放预览。

## 当前功能

- 成功与错误提示使用右上角浮动通知，可关闭并自动消失，不挤占画布。
- 左侧为素材、同步与元素库，中间为预览画布，右侧为所选元素设置与数据采样/海拔；移除重复标签与常驻操作说明，必要帮助通过控件悬停提示提供。
- 多段 GPX 导入、启停、移除和时间拼合；支持任意素材导入顺序和文件拖放。
- 图片或视频背景；无背景时显示透明棋盘，纯 GPX 使用独立播放时钟。
- 可配置的速度平滑、刷新间隔、GPS 航向和累计距离。
- 右侧播放器底部叠加速度/海拔曲线，共用时间轴与播放指针；曲线默认收起，导入新的 GPX、视频或图片后也会收起；播放器右上角的「曲线」按钮可收起/展开，收起后保留播放与时间轴，并释放画布空间。悬停显示对应时刻的采样详情，点击曲线定位播放；聚焦后可用左右键移动 1 秒、Shift 移动 10 秒，Home/End 跳到首尾。速度复用当前平滑与归零设置，双纵轴分别使用 km/h 和米；缺失值与断档不连线，视频对齐后只绘制当前预览时段。
- 自定义 SVG 字段绑定，以及可手动添加的透明数据条。
- 左上角「文件」提供预设载入、命名保存与打开预设文件夹；工程保存/加载入口已移除。预设保存布局与采样配置。
- 右侧画布上的速度、经纬度组件可自由拖动、缩放、显示/隐藏、锁定。
- 元素大小支持从 0% 调整到画布允许的最大尺寸，可拖动滑块或直接输入百分比；0% 不渲染，仍可从图层列表选中并恢复。
- 可调整位置百分比、大小、背景透明度、强调色；拖动时支持画布边缘、中心、安全边距，以及其他可见元素的边缘、中心和 8px 间距吸附，触发距离为 7px。锁定元素仍可作参照，隐藏元素不参与；显示实时参考线，按 Alt 临时关闭吸附。
- 画布元素右键可删除，聚焦画布元素后按 Delete/Backspace 也可删除，均可撤销；编辑输入框时不会误删元素。
- 支持撤销/重做、方向键逐像素微调，Shift + 方向键移动 10 像素。
- 播放/暂停、拖动时间轴、静音、回到视频起点；Space 切换播放。
- 按视频时间采样 GPX，速度显示为 km/h；经纬度保留 WGS84，不自动转换为 GCJ-02。

## 自动时间对齐

计算方式：

```text
偏移秒数 = (视频起始时间 − GPX 起始时间) / 1000
当前 GPX 时间 = GPX 起始时间 + 偏移秒数 × 1000 + 视频播放时间 × 1000
```

正偏移表示视频开始于 GPX 记录之后；负偏移表示视频先于 GPX 开始。偏移可为小数。

桌面端优先通过可选的 `ffprobe` 读取 QuickTime 拍摄时间、容器/视频流 `creation_time`，保留时区与毫秒。没有 `ffprobe` 时仍可直接读取 MP4/MOV 的 `mvhd` 时间，并通过系统 WebView 播放视频。浏览器开发模式读取 MP4/MOV 的 `mvhd` 时间。读取大型文件时只读取元数据块，不把整段视频载入内存。

- 时间戳统一换算为 UTC；界面中的日期与手动输入使用当前系统时区。
- 每段 GPX 支持「UTC 标注校正」，默认不校正。若设备把本地时间误写成 `Z`（UTC），选择实际记录时区。例如 `2026-10-22T18:39:45.000Z` 实际表示东八区 18:39:45 时，选择 `UTC+08:00（东八区）`，校正后的绝对时间为 `2026-10-22T10:39:45.000Z`，东八区界面显示 18:39:45。正确带时区的文件保持「不校正（按文件）」。
- 校正应用于该来源的全部轨迹点，再进行拼合、采样和视频对齐；不修改原始导入数据，切换时区不会累计偏移。设置随工程保存，旧工程默认不校正。当前支持固定 UTC 偏移，不自动处理夏令时。
- 缺少有效拍摄时间时明确提示，并允许手动填写视频起始时间或设置偏移；不使用文件修改时间猜测。
- 元数据可能是剪辑、转码或设备时钟设置产生的时间，用户可手动校准。
- 超出 GPX 覆盖范围、跨轨迹段、孤立定位点或相邻点相隔超过 30 秒时显示 `—`，实时速度、坐标不保持旧读数或跨断档插值；行程累计值独立处理。每段获得第二个定位点前，速度显示 `—`，不借用未来速度；有定位坐标但无法估算速度时保留坐标。刷新快照也必须服从当前实际时间的覆盖范围。
- GPX 支持多个 `trk/trkseg`，要求至少两个有效的带时间戳轨迹点；排序并忽略重复时间和缺少时间的点。
- 视频播放能力取决于系统 WebView 与解码器，建议使用 H.264 MP4。这个版本不自动转码。

macOS 可选安装元数据增强工具：

```sh
brew install ffmpeg
```

## 平滑、刷新与航向

默认 **7 个定位点**的居中窗口（当前点与前后各 3 点），可选择 3–61 的奇数点数或关闭平滑。参考 [gpx.studio 的双向窗口速度统计](https://github.com/gpxstudio/gpx.studio/blob/main/gpx/src/gpx.ts#L906-L922)，用窗口累计路程除以实际经过时间，而不是平均各点瞬时速度；时间分母至少 1 秒。上游按时间选择窗口，本项目按点数选择，采样不规则时不会把 7 点误当成 7 秒。窗口在连续段首尾截短，不跨分段、断档或异常末点。居中平滑会使用窗口内后续定位点，起停变化可能提前反映在平滑速度中；但每段首点与首个观测区间仍不显示速度。随后用单调三次 Hermite 曲线补足采样间隔，避免速度过冲或负值。

额外识别孤立的往返 GPS 跳点：只有两侧速度都显著高于相邻运动速度、且绕行距离明显大于直接连接时，才在速度与航向估计中用相邻可信点的插值替代。正常持续高速和转弯不设置固定限速。该保护不能识别所有持续定位偏差；原始坐标、原始点速度、工程素材和累计距离均不改写。末点没有后续定位来验证：若最后一段的速度突增超过此前若干有效区间的中位水平，会标记为速度无效并显示 `—`，不强行填 0 或维持旧读数。关闭平滑时使用原始点速度并关闭内部往返跳点修正，首点和异常末点的有效性检查仍生效。被标记为无效的末点不参与前面各点的窗口累计，避免异常距离向前扩散。断档和显式分段之间不计算窗口。

速度归零阈值默认 **0.5 km/h**，可在数据采样中调整，0 表示关闭。平滑插值后的速度低于阈值时显示 0；同一连续段中沿用最后有效航向，不受低速漂移影响，也不跨断档继承方向。首次有效运动前没有可靠航向时显示 `—`。阈值随工程和预设保存，旧文件默认 0.5 km/h。此设置不改写原始坐标或累计距离。

窗口点数随工程和预设保存为 `smoothingPoints`。旧文件的 `smoothingSeconds` 仅用于兼容读取：原为 0 时保持关闭，正值迁移到默认 7 点，不把秒数直接当点数。

默认每 0.2 秒更新一次数据快照。刷新间隔与播放器帧率分开控制，SVG、速度和航向共享同一份采样快照。

航向使用球面初始方位角，正北 0°、正东 90°，顺时针增加；跨 359°/1° 按最短角度插值。小于 0.5 米的位移视为无法可靠定向，保留当前连续段内最后一个有效航向；新段没有有效方向时显示 `—`。航向和累计距离缓存在处理后的轨迹点及当前预览状态中。

## 多段 GPX 与轨迹预览

- 所有点按绝对时间排序，不把文件起始时间强制接到前一个文件末尾。
- 后导入的文件覆盖其连续记录区间中的旧点，避免两个重叠采样流交替产生速度尖峰。
- 可逐段启停或移除。默认允许连接不同文件的相邻点：间隔不超过 30 秒，且推算速度不超过 100 m/s；可取消连接。原文件的显式分段与较长断档始终保留。
- 时间轴分别显示每段有效覆盖范围，不把空档涂成有效数据。
- 轨迹缩略图使用含纬度修正的等距圆柱投影、日期变更线展开、统一缩放与 Ramer–Douglas–Peucker 简化；保持纵横比例和转弯，断档不连线，并标注当前位置。它是路线概览，不是在线地图底图。

## 叠加层视频导出

桌面版右上角「导出视频」可设置分辨率、0.1–120 fps 帧率和导出起止秒数。默认帧率推荐为数据刷新间隔的倒数（0.2 秒对应 5 fps），减少重复渲染与编码可加快导出；仍可手动提高帧率。默认优先提供 WebM / VP9 透明导出，也支持 MOV / ProRes 4444 与 MOV / PNG 无损，均保留透明通道；选择「绿幕」后默认使用体积更小的 MP4 / H.264，也可选 MOV。绿幕为纯绿色（#00FF00），不含 Alpha，需在剪辑软件中抠像，半透明边缘可能损失。ProRes 4444 便于后期编辑但文件较大，PNG 是另一种无损编码选择。VP9 使用软件编码与有损压缩（CRF 30），通常比 MOV 更小；剪辑软件需支持 WebM Alpha，使用 FFmpeg 解码透明 WebM 时应指定 `-c:v libvpx-vp9` 作为输入解码器。需安装本地 FFmpeg（macOS：`brew install ffmpeg`），浏览器开发预览不编码视频。

输出包含当前可见元素及其位置、尺寸、配色和背景不透明度；背景视频、图片、棋盘格、编辑选框及播放器曲线均不导出。输出比例与画布不同时等比居中，空白区域随所选模式保持透明或纯绿。导出复用预览的速度平滑、归零阈值、航向、刷新间隔及视频时间偏移；断档时实时数据显示缺失值；当前/剩余里程保持最近的已知距离；剩余记录时间、UTC 时钟与行程时间进度按当前时间继续变化，轨迹前为 0/全程，轨迹结束后为全程/0。拖动到任意时间也能得到相同结果。帧数为 `ceil(导出时长 × fps)`，最后一帧在选定结束时间之前，输出时长向上取整到一帧。

前端以同一套 SVG 渲染内置和自定义元素，直接传输元素占用区域的 RGBA 像素；Rust 补齐完整背景后编码，避免逐帧 PNG 压缩与解压。同一画面可批量复用，输出仍保持设定帧率。只保留当前帧与元素缓存，不将整个视频载入内存。默认「优先硬件编码」跨平台检查 FFmpeg 已安装的编码器，按当前分辨率与帧率实际探测：H.264 尝试 VideoToolbox、NVENC、Quick Sync、AMF、VAAPI 与 V4L2；绿幕 VP9 尝试 Quick Sync/VAAPI；ProRes 尝试 VideoToolbox 且须通过 Alpha 解码检查。Linux VAAPI 会尝试可用渲染设备；每次硬件探测有超时保护。透明 VP9 与 PNG 没有支持当前 Alpha 管线的硬件路径，保留软件编码；不可用时自动使用软件编码，也可手动关闭。进度栏显示实际编码方式。导出有进度和取消按钮；失败或取消会清理临时输出，成功后才替换目标文件，并禁止覆盖当前预览视频。关闭窗口会取消其导出任务。素材与视频均在本地处理。

## SVG 元素

在「画布元素」中按运动、行程、时间、导航分类，通过缩略图选择添加元素，或导入 SVG，或选择「添加数据条」一次添加航向、经纬度、时间、距离、海拔和速度六个独立元素。行程分类还可添加当前里程、剩余里程、剩余时间、总里程、总时长与进度。每项可单独拖动、缩放、隐藏、锁定，图层行右侧可直接删除，也能通过「添加数据项」单独添加。已有工程中的旧版内置数据条可选中后点击「拆分数据条」，保留位置、比例及外层样式；拆分和整组添加均支持一次撤销。自定义 SVG 保持原样。元素默认无背景；背景不透明度可设为 0–100%。桌面端从操作系统读取所有可用字体（含用户安装字体），字体下拉支持搜索、键盘选择与刷新；中文字体名随工程和预设保存。浏览器开发模式在支持时使用 Local Font Access，需要浏览器授权，否则提供常见字体。每个元素可单独设置字体、主字号、粗体和斜体；单位与辅助文字保持相对字号，设置同步用于预览、导出和工程/预设。SVG 中已转换为路径的字形不能改字体。SVG 自带的背景矩形和布局由作者决定，外层背景设置不会改写 SVG 内部设计。

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 500 120">
  <text x="20" y="70" font-size="48" fill="{$Color}">{$Speed} km/h</text>
  <g opacity="{$HasHeading}" transform="rotate({$Heading} 430 60)">
    <path d="M430 30 L415 80 L430 70 L445 80Z" fill="white"/>
  </g>
</svg>
```

| 字段                           | 含义                               |
| ------------------------------ | ---------------------------------- |
| `{$Speed}`                     | km/h，一位小数                     |
| `{$Latitude}` / `{$Longitude}` | WGS84 十进制度，六位小数           |
| `{$Elevation}`                 | 海拔米，一位小数                   |
| `{$Heading}`                   | 正北为 0° 的航向，一位小数         |
| `{$Distance}`                  | 累计公里，两位小数，不计跨断档距离 |
| `{$RemainingDistance}` / `{$TotalDistance}` | 剩余/总里程（km） |
| `{$RemainingTime}` / `{$TotalTime}` | 剩余/总 GPX 记录时间（不是预测到达时间） |
| `{$Progress}` | 已完成记录时间百分比（0–100），断档继续变化 |
| `{$ProgressRatio}` / `{$ProgressPercent}` | 时间进度 0–1 / 0–100 的高精度图形数值 |
| `{$DistanceProgress}` | 已知里程百分比，缺少 GPS 时保持最近距离 |
| `{$Elapsed}`                   | 当前播放时间                       |
| `{$Timestamp}`                 | 当前快照的 UTC ISO 时间            |
| `{$Color}`                     | 元素强调色                         |
| `{$HasData}` / `{$HasHeading}` | 1 或 0，可用于透明度               |
| `{$HasSpeed}` | 速度有效时为 1；未获得足够定位或速度无效时为 0 |

SVG 保留 viewBox、局部渐变和样式；脚本、HTML、外部资源与事件处理器会被清理。模板以独立 SVG 图片渲染，样式不影响编辑器。上限 2 MB。图片背景支持 PNG/JPEG/WebP/GIF/AVIF，上限 20 MB。

数据条参考了用户提供的 [gpxutil](https://github.com/DingJunyao/gpxutil) 画面布局方向，自行实现了方向、经纬度、时间、距离、海拔、速度字段，不包含道路名称或逆地理编码。

## 预设

- **保存预设**：输入独立的预设名称，同名保存更新原预设；`.preset.json`，只包含元素、样式、画布比例与采样设置，载入时不替换当前素材。
- 视频仅保存引用与元数据，不复制或内嵌视频。桌面端尝试恢复本地路径；路径失效或浏览器重开时会提示重新关联，同名视频重新导入后恢复偏移和播放位置。
- 桌面端直接保存到 Tauri 配置目录的 `projects/` 与 `presets/`，同名保存更新原文件，改名可另存。打开/载入时先展示本地库，按最近修改排序，也可从文件导入。写入采用临时文件加原子替换；浏览器以 JSON 下载/上传。无后台上传或云存储。工程上限 100 MB。

## 工程结构

```text
ui/
  App.vue                页面组装与依赖注入
  editor/                编辑器组合入口、类型化上下文
  components/
    shell/               应用头部与消息提示
    inspector/           素材、同步、图层、属性面板
    canvas/              画布工具栏、预览、播放控制
    widgets/             速度、经纬度与可拖动组件外壳
  composables/           按功能独立的状态与交互控制器
  domain/                数据模型、轨迹采样与纯计算
  infrastructure/        浏览器/Tauri 素材访问、GPX 与 MP4 解码
  lib/                   展示格式化工具
  styles/                按界面职责划分的样式
  tests/                 前端回归测试
src-tauri/
  src/
    main.rs              二进制入口
    lib.rs / app.rs      模块装配与 Tauri 启动
    commands/            IPC 适配、后台调度、WebView 文件授权
    application/         GPX 导入、视频导入、字幕与地图用例
    domain/              轨迹模型、速度/时间采样、时间对齐
    infrastructure/      GPX 解码、文件系统、ffprobe、MP4、SRT、地图渲染
  tests/                 不依赖个人文件或网络的集成测试
Cargo.toml / Cargo.lock  唯一的 Cargo workspace 与依赖锁
```

界面组件只负责展示和事件绑定；composables 按素材、对齐、播放、画布尺寸、组件布局、时间轴、快捷键与文件拖放分别管理状态。`editor/createEditor.ts` 只组合这些控制器，`editor/context.ts` 向组件提供类型化上下文。

Rust 依赖方向为 `commands → application → domain / infrastructure`，基础设施实现依赖领域类型，领域层不依赖 Tauri、文件系统或命令层。所有 Rust 源码已统一迁入 `src-tauri`，根 `src/` 与独立的 `pov-core` 工程已合并。

原有 SRT 功能位于 `application/subtitle_export.rs`，以显式输出路径调用；地图实验位于 `infrastructure/map_renderer.rs`，通过可选的 `map-rendering` feature 启用，地图 I/O 不再放在轨迹点模型里。这些库功能不作为编辑器的合成导出入口。

桌面导入使用 Rust 解析 GPX。浏览器开发模式保留 TypeScript 解析适配；两者均有覆盖重复点、断档、时区与跨日期变更线的测试。播放逐帧更新在前端完成，不进行逐帧 IPC。

Hikari 采用官方 Vue 源码包，按需引入组件和样式，并使用 Vue JSX 插件编译 TSX。版本由 `pnpm-lock.yaml` 锁定。

导航分类可添加路线 SVG：支持全程或按前后时长截取局部路线，保留断档，标示当前位置及方向，可选择航向朝上；轮廓与采样缓存复用，随布局导出。

当前不提供背景视频合成或 HEVC 预览代理。预设需手动保存。

### SVG 动态图形范例

指针时速表与速度进度条位于「运动」，进度环位于「行程」；每个范例卡片可打开源文件位置，已导入 SVG 也可在右侧属性标题处打开源文件位置。原文件失效或发行版没有源码目录时，在配置目录生成可查看的 SVG 副本；浏览器模式下载源码。范例源文件位于 `ui/examples/`，可自行修改后导入。

SVG 通过数值字段控制几何图形，不执行 JavaScript 或任意表达式：

- `{$SpeedRatio}`：当前速度 / 元素「速度满刻度」，限制在 0–1，适合 `scale({$SpeedRatio} 1)`。
- `{$SpeedPercent}`：0–100，适合路径 `pathLength="100" stroke-dasharray="{$SpeedPercent} 100"`。
- `{$SpeedAngle}`：−90° 到 +90°，适合以中心点旋转半圆时速表指针。
- `{$SpeedColor}`：满刻度 50% 以下绿色、50–80% 黄色、80% 以上红色。
- `{$HasSpeed}`：速度缺失时为 0；图形用它控制透明度，文字速度仍显示 `—`。
- `{$ProgressPercent}`：行程时间百分比，用于圆环 `stroke-dasharray`；GPX 断档时继续前进。数字标签可用 `{$Progress}`，按已知距离统计时用 `{$DistanceProgress}`。

满刻度默认 60 km/h，每个元素可独立调整。速度超过满刻度时图形停在最大值，数字继续显示真实速度。静态打开范例不会自动采样，动态字段由本应用在预览和导出时替换。


### 小地图

导航分类中「路线」「小地图」使用当前 GPX 生成缩略图；添加小地图后可在右侧选择 OpenStreetMap 或高德地图。高德使用官方静态地图 API，需先配置自己的 Web 服务 Key（只保存在本机配置目录，不进入预设）；采用本地 WGS84→GCJ-02 近似转换，不修改原始轨迹。高德最大缩放 17 级，API 按 64 像素区域复用图像。

OpenStreetMap 小地图支持圆形/方形、2–19 级缩放、路线叠加和航向朝上。仅在显式添加/载入小地图后按当前视图联网请求，不上传整条 GPX。桌面端由 Rust 获取并缓存瓦片至少 7 天，浏览器开发模式使用 HTTP 缓存；没有后台预取。透明视频导出也包含地图、当前位置和署名，嵌入瓦片避免跨域污染画布，加载失败会提示并中止导出。地图需网络或本地已有缓存，离线纯路线元素不依赖网络。OSM 使用 WGS84/Web Mercator；高德显示时另做坐标转换。

地图署名始终显示，使用遵守 [OSM 瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)。地图服务会收到所请求瓦片的位置与网络信息；较长导出会按需加载经过区域的瓦片。


### 海拔补全与替换

右侧数据采样中的「海拔」提供「替换原始数据」按钮，一次获取已启用轨迹的地形海拔并替换显示值；完成后可用旁边的恢复按钮还原原始海拔。参考 [gpx.studio 的取样方法](https://github.com/gpxstudio/gpx.studio/blob/main/website/src/lib/utils.ts)，直接连接 [Mapterhorn 官方瓦片服务](https://mapterhorn.com/data-access/)：12 级、512×512 WebP Terrarium 瓦片，按 `R×256 + G + B/256 − 32768` 解码并双线性插值。桌面端由 Rust 下载、缓存、解码和采样；按瓦片合并请求，不逐个定位点重复下载。

原始 GPX 海拔保留；替换值独立保存，可「恢复原始」，并随工程保存/恢复。无有效地形数据的点保留原值，不把失败填成 0；网络失败不应用本次更改。支持进度与取消，取消后不应用正在获取的结果（当前网络请求最多等到超时结束）。浏览器开发预览不提供地形获取，需在桌面版操作。地形海拔与设备测得的海拔可能存在差异；数据来源见 [Mapterhorn 署名](https://mapterhorn.com/attribution/)。

高德静态地图接口及 Key 说明见[官方文档](https://lbs.amap.com/api/webservice/guide/api/staticmaps)。保留服务返回图像底部署名；API 配额取决于自己的账号。
